0. 한 줄 요약
--------------------------------------------------------------
 "수협 면세유 단가(경유·휘발유)를 가격판처럼 입력하면,
  공공 API로 자동 수집한 오늘의 주유소 평균가와 바로 비교해 보여주는 사이트.
  서버 없이 GitHub만으로 운영하고, 데이터는 GitHub Actions가 자동 갱신한다."

1. 무엇을 만들었나
--------------------------------------------------------------
 [화면 구성]
  1) 오늘 면세유 단가 입력
     - 주유소 가격판처럼 경유·휘발유 단가만 입력
     - 단위 선택: 원/드럼(1드럼=200L) 또는 원/L
     - 비교 지역 선택: 전국 평균 또는 시도별
  2) 비교 결과
     - "일반 주유소보다 L당 OOO원(OO%) 저렴"
     - 막대 그래프: 면세유(입력값) vs 주유소 평균
     - 드럼당 절감액 = (주유소가 - 면세유가) x 200L
     - 참고용 한 줄: 국제 도매가(뉴욕항 현물가 환산)
  3) 변동 시나리오 (슬라이더)
     - 국제 유가 -30%~+30%, 환율 -100원~+100원을 움직이면
       국제 도매가 / 주유소 평균 / 입력한 면세유 단가가 얼마나 변할지 계산
     - 프리셋 버튼: 유가 +10%, 유가 -10%, 환율 +50원, 고유가·고환율, 초기화
     - 계산 방식: 도매가 변화분 x 반영 비율(기본 100%)을 소매가에 그대로 더하는
       단순 추정 (세금·마진 고정, 시차·계약·정책 미반영 -> 참고용)
  4) API로 가져온 시장 데이터 카드 8개
     - 주유소 경유·휘발유 평균(7일 추이), 원/달러 환율,
       두바이유·브렌트유·WTI, 뉴욕항 경유·휘발유 현물가
     - 카드에 마우스를 올리거나(PC) 누르면(모바일) 설명이 뜸
  5) 우측 상단 [연계 API · 수집 주기] 버튼 -> 설명 팝업 (발표용)
  6) 상단 상태 표시: 5개 API별 정상(초록) / 이전값 유지(노랑) / 실패(빨강)

 [기존 자료와의 차이]
  처음에 받은 시연 HTML은 모든 가격이 숫자로 직접 적혀 있었고
  API 호출 코드가 없었다. 그래서 기존 파일을 고치지 않고,
  "면세유 단가 입력 + 실시간 유가 비교"만 남겨 새로 만들었다.

2. 왜 이런 구조인가 (핵심 개념: CORS)
--------------------------------------------------------------
 문제
  - 웹페이지(브라우저)가 공공 API를 직접 부르면
    브라우저 보안 정책(CORS)에 막히는 경우가 많다.
  - HTML을 GitHub에 올린다고 이 문제가 저절로 해결되지는 않는다.
    (PC에서 열든 GitHub Pages에 올리든 브라우저 규칙은 동일)

 해결
  - GitHub Actions는 브라우저가 아니라 "서버"에서 실행되므로
    CORS 제한을 받지 않는다.
  - Actions가 대신 API를 호출해 결과를 data.json 파일로 저장하고,
    웹페이지는 같은 사이트 안의 data.json만 읽는다.

 얻은 것
  - 별도 서버 설치·운영 불필요 (비용 0원)
  - API 인증키가 웹페이지에 노출되지 않음 (GitHub Secrets에 비공개 보관)
  - 사용자가 접속할 때마다 API를 호출하지 않아 API 호출 한도 부담이 적음

5. 데이터는 GitHub를 통해 언제 갱신되나
--------------------------------------------------------------
 [갱신(수집+배포)이 일어나는 3가지 경우]
  A. 예약 자동 실행
     - 설정: 매시 23분 (cron '23 * * * *')
     - 실측: 매시간 정확히 돌지는 않음.
             GitHub이 무료 저장소의 예약 실행을 서버 사정에 따라 늦추거나 건너뜀.
             관측 사례(한국시간): 10/11 23:02, 10/12 03:54, 10/12 07:54
             -> 약 4시간 간격으로 실행됨
     - 하루 평균 5~6회 갱신된다고 보면 됨
  B. 수동 실행
     - GitHub 저장소 > Actions > "유가 수집 및 Pages 배포" > Run workflow
     - 약 30초~1분 안에 최신값으로 갱신 -> 시연 직전에 누르면 안전
  C. 코드 수정(push) 시
     - 파일을 고쳐 올릴 때마다 자동으로 한 번 실행

 [화면에서 확인하는 법]
  - 우측 상단 "시장 데이터 수집 시각"과 "OO분 전" 표시
  - 상단 API 상태 점 (초록/노랑/빨강)
  - 2026-10-31 18:48 수집분이 화면에 표시되는 것을 캡처로 확인함
    (첫 배포 후 3주가 지나도 자동 수집이 계속 동작)

 [실패했을 때 동작]
  - 접속이 끊기면 2초, 5초 뒤 자동 재시도
  - 그래도 실패하면 직전에 성공한 값을 "이전값"으로 유지
    -> 카드가 회색으로 표시되고 상태 점이 노란색
  - 표시할 값이 아예 없을 때만 빨간색

 [60일 규칙과 대응]
  - GitHub은 60일 동안 저장소에 활동이 없으면 예약 실행을 자동으로 끈다.
  - 대응: keepalive.yml이 매월 1일 수집 워크플로를 다시 "사용"으로 설정
  - 혹시 멈춰도 Actions 화면의 [Enable workflow] 버튼으로 바로 재개 가능

6. 어떻게 만들었나 - 실제 프롬프트 흐름
--------------------------------------------------------------
 (AI와 나눈 실제 대화 순서입니다. 발표 때 그대로 보여주기 좋습니다.)

 [1단계] 가능한지부터 물어봄
   프롬프트(요약 원문):
   "면세유 가격 입력시 실시간 api 조회를 통한 결과조회하는걸 구현해 보고 싶어.
    CORS 때문에 어렵다는데 GitHub에 올림 가능해? API키는 개인 테스트로
    받은거라 그냥 써도 된다. 우선 확인해줘. 다른 기능은 불필요하고
    실시간 유류 정보들을 가져와 금일 면세유 가격 입력시 결과 확인 용도"
   (기존 시연 HTML 파일과, 다른 AI가 제안한 "GitHub Actions로 수집" 설명을 함께 첨부)
   -> AI 응답: 가능하지만 HTML만 올려서는 CORS가 해결되지 않는다.
      Actions로 대신 수집하는 구조를 제안하고, 필요한 정보 3가지를 질문함.

 [2단계] 질문에 답하고 의도를 맡김  (핵심 포인트)
   프롬프트(요약 원문):
   "(API 5종의 이름과 키 전달)
    API로 실시간 가져온 값들을 실제 담당자가 입력한 값과 비교 정도.
    주유소 앞에 경유 얼마 휘발유 얼마같이 가격만 넣음 안되나?
    내 전문분야가 아니라 너가 내 의도를 잘 파악해 제안해줘.
    public 시연시 활용할 예정이야"
   -> AI가 가격판 입력 방식 + 주유소 평균가 비교 화면을 설계해 구현
   -> 키를 코드에 직접 넣어 올리려 하자 보안 정책이 차단 ->
      키를 GitHub Secrets에서만 읽도록 변경 (아래 시행착오 참고)

 [3단계] 사용자가 직접 설정하고 확인 요청
   "설정 다 했어 확인해줘"
   -> Secrets 5개 등록, Pages 켜기 후 AI가 Actions 실행 로그로
      5개 API가 실제로 값을 받는지 하나씩 확인

 [4단계] 화면을 보면서 다듬기 (한 번에 한 가지씩 요청)
   - "국제 도매가는 참고로만 작게 표시해줘"
       -> 비교 막대에서 빼고 회색 작은 글씨 참고 문구로 이동
   - "우측 상단에 간단히 뭘 연계한건지 어떤 주기로 제공하는지.
      내가 시연시 간단히 설명 가능하게 팝업 버튼 만들자"
       -> [연계 API · 수집 주기] 팝업
   - "각 카드위에 마우스 올림 해당 사항이 뭔지 간단 설명 보이게 반영해줘"
       -> 시장 데이터 카드 툴팁 (모바일은 탭)
   - "비교 결과 카드에도 설명 툴팁 넣어줘"
       -> '? 설명' 버튼 툴팁
   - "(스크린샷) 위에 빨간 동그라미는 무슨뜻?"
       -> 접속 오류가 원인임을 로그로 확인, 재시도 + 노란색 상태 + 범례 추가
   - "(스크린샷) 휴대폰에서는 깔끔한데 PC에서는 글자도 작고
      꽉차보이지도 않아. 개선해 반영해줘"
       -> 화면 크기에 맞춰 글자·여백이 커지도록 개선

   - "해당 연계데이터로 면세유 가격 넣고 비교까지는 했는데 이걸 더 확대해
      다른 유용한 기능을 제공하고 싶은데 뭐가 있을까?"
       -> AI가 후보 10가지를 난이도·주의점과 함께 제안 (아래 '다음 확장 아이디어')
   - "변동 시나리오 슬라이더 반영해 보자"
       -> 유가·환율 슬라이더로 국내 가격 변화를 추정하는 섹션 추가

 [5단계] 운영 관련 궁금증을 질문으로 해결
   - "Action이 주기적으로 수집하는 기능이야?"
   - "60일 마다 갱신은 무슨말?" -> "보조 워크플로 추가해줘"
   - 예약 실행이 안 돌 때 -> 대안 중 "A"(기본 브랜치 main 정리)를 선택


   ※ 확장 아이디어를 물을 때는 "뭐가 있을까?"처럼 열어 두고 묻고,
     마음에 드는 것을 골라 "반영해 보자"로 이어가면 편하다.

7. 이번에 효과가 컸던 프롬프트 요령
--------------------------------------------------------------
 1) 구현 전에 "가능한지 우선 확인해줘"로 시작 -> 헛수고 방지
 2) 목적과 범위를 먼저 말함
    ("다른 기능은 불필요", "결과 확인 용도", "public 시연용")
 3) 전문분야가 아니면 "내 의도를 파악해 제안해줘"라고 맡김
    -> AI가 질문을 되묻고 설계안을 제시
 4) 한 번에 한 가지씩 요청하고, 결과 화면(스크린샷)을 보여주며 수정 요청
 5) 모르는 용어는 바로 질문 ("빨간 동그라미는 무슨 뜻?", "60일이 무슨 말?")
 6) 직접 해야 하는 설정(키 등록, Pages 켜기)은 AI가 단계별로 안내
    -> 끝나면 "했음"이라고 알리면 AI가 로그로 검증

9. 시행착오와 해결 (실제로 겪은 문제)
--------------------------------------------------------------
 1) API 키를 코드에 넣어 올리려다 차단됨
    -> 공개 저장소에 키가 노출되는 것을 보안 정책이 막음.
       키는 GitHub Secrets에 등록하고 코드에는 이름만 사용.
 2) 첫 배포 실패 "Pages not enabled" (404)
    -> Settings > Pages 에서 Source를 GitHub Actions로 변경.
 3) 오피넷이 빈 목록으로 응답
    -> 서버 연결은 정상. 키 문제로 판단하고 키를 다시 확인해 재등록한 뒤 정상.
       (오피넷은 키가 틀려도 오류가 아니라 빈 목록을 돌려줌)
 4) 수출입은행 "인증코드 오류"
    -> 키를 다시 확인해 재등록한 뒤 정상.
 5) 간헐적 접속 끊김으로 빨간 점
    -> 미국(GitHub) 서버에서 국내 기관에 접속할 때 가끔 끊김.
       자동 재시도 2회 + "이전값 유지" 노란색 상태로 개선.
 6) 예약 실행이 한동안 안 돎
    -> 등록 후 약 8시간 뒤에야 첫 예약 실행이 시작됨.
       기본 브랜치를 main으로 정리하고 cron 시각을 바꿈.
       정확한 원인은 확정하지 못함 (GitHub 쪽 지연 가능성).
 7) 모바일에서 툴팁 글이 잘림 / PC에서 글자가 작음
    -> 레이아웃과 글자 크기 단위를 화면 크기에 맞게 수정.


--------------------------------------------------------------
10. 한계와 주의점 (발표 때 솔직하게 말할 부분)
--------------------------------------------------------------
 1) "실시간"이 아니라 "마지막 수집 시점" 기준이다.
    - 예약 실행 간격이 매시간이 아니라 약 4시간. 필요하면 수동 실행.
 2) 면세유 단가는 공개 API가 없어 담당자가 직접 입력한다.
    - 수협 공지(PDF 등)로만 공개되므로 자동 수집 불가.
 3) 주유소 평균가는 세금이 포함된 가격이다.
    - 면세유와의 차이는 대부분 "면제된 세금" 몫.
 4) 국제 가격은 미국 시장 기준이며 발표가 늦다.
    - 국내 가격은 싱가포르 시장을 기준으로 하므로
      국제 도매가는 "시장 흐름 참고용"으로만 쓴다.
    - 원유(브렌트·WTI·두바이)의 원/L 환산값은 정제 전 가격이라
      경유·휘발유 가격과 직접 비교할 수 없다.
 5) 수협 공식 서비스가 아닌 "공개자료 기반 시연 화면"이다.
 6) 공개 저장소이므로 키는 코드에 넣지 않고 Secrets로만 관리한다.

11. 예상 질문 & 답변
--------------------------------------------------------------
 Q. 서버가 없는데 어떻게 자동으로 갱신되나요?
 A. GitHub Actions라는 무료 자동 실행 기능이 정해진 시간에 프로그램을
    돌려 데이터를 새로 만들고, GitHub Pages가 그 결과를 웹에 올립니다.

 Q. 왜 웹페이지에서 API를 직접 부르지 않았나요?
 A. 브라우저 보안 정책(CORS)에 막히는 API가 많고, 직접 부르면 API 키가
    화면 코드에 노출됩니다. 중간(Actions)에서 대신 받으면 둘 다 해결됩니다.

 Q. 비용이 드나요?
 A. 공개 저장소의 GitHub Actions/Pages는 무료, 사용한 공공 API는 무료
    개인 키입니다. 서버 비용이 없습니다.

 Q. 데이터가 틀리면 어떻게 하나요?
 A. 각 카드에 출처와 기준일이 표시됩니다. 국제 가격은 며칠 늦게 발표되므로
    기준일을 함께 봅니다. API가 실패하면 직전 값을 노란색으로 표시합니다.

 Q. 면세유 가격도 자동으로 가져올 수 없나요?
 A. 수협 면세유 가격은 공개 API가 없고 공지 파일로만 제공되어,
    담당자가 입력하는 방식으로 설계했습니다.

 Q. 개발을 전혀 몰라도 만들 수 있나요?
 A. 이 사이트는 AI와의 대화로 만들었습니다. 다만 API 키 발급,
    GitHub 설정(Secrets, Pages)처럼 직접 해야 하는 단계는 있고,
    AI가 단계별로 안내했습니다.

 Q. 시연 도중 데이터가 오래돼 보이면?
 A. Actions 화면에서 Run workflow를 누르면 1분 안에 최신값이 됩니다.

12. 시연 진행 순서 (약 5분)
--------------------------------------------------------------
 1) 사이트 접속 -> 상단 API 상태 점과 "수집 시각" 보여주기 (1분)
 2) 우측 상단 [연계 API · 수집 주기] 팝업으로 구조 설명 (1분)
 3) 가격판에 오늘 면세유 단가 입력 -> 비교 결과 확인 (1분)
    예시 입력: 경유 248,920원/드럼  (또는 "예시값 넣기" 버튼)
 4) 시나리오 슬라이더로 "유가 +20%, 환율 +50원이면?" 보여주기, 시장 데이터 카드 설명 (1분)
 5) GitHub 저장소 > Actions 화면에서 자동 수집 이력과
    Run workflow(수동 실행) 보여주기 (1분)
 6) 프롬프트 흐름(6장)으로 "어떻게 만들었는지" 마무리
